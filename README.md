# digital-clock-board

터미널 분할의 한쪽에 상시 띄워 두는 레트로 디지털 시계. 같은 자리 짝인 `server-status-board`와 터미널에서 나란히 봤을 때 테두리 폭이 맞도록 크기를 맞춰 뒀다.

## 실행

```
cd digital-clock-board
npm install
npm start
```

종료는 Ctrl+C. 터미널을 분할해서 `server-status-board`와 한쪽씩 나눠 띄운다. `npm start`는 `node --watch index.js`라 소스를 고치면 자동으로 재시작된다(Node 18.11+ 내장 기능) — 매번 수동으로 Ctrl+C → 재실행하던 걸 대신해 준다. 그냥 `node index.js`로 직접 띄워도 똑같이 동작하고 재시작만 안 될 뿐이다.

## 화면 구성

- 제목 `Y O U   G O T   T H I S`(사용자 응원 문구, 기존 `D I G I T A L   C L O C K`에서 교체)
- 5줄 LED 폰트로 그린 큰 시계(`HH:MM:SS`, 초마다 콜론이 깜빡인다), 양옆에 산 — 잔디 카펫과 같은 `▒` 문자로 그리고, 각 쌍마다 삼각형 두 개(꼭대기까지 닿는 far, 40% 지점부터 시작하는 near)를 왼쪽=far·오른쪽=near로 겹쳐서 위쪽은 봉우리 두 개가 따로 보이다가 바닥 줄에서 하나의 능선으로 합쳐지게 했다. far는 `#045926`(어두운 녹색, 더 멀리 있는 산을 표현), near는 시계와 같은 `#00FF66`로 칠한다 — 겹치는 칸은 near(가까운 쪽)가 far를 가리는 걸로 보고 near 색을 쓴다. 왼쪽·오른쪽 두 산 쌍 다 같은 식을 쓰므로 "각 쌍의 왼쪽 산이 더 멀다"는 규칙이 양쪽에 똑같이 적용된다. 꼭대기는 1칸짜리 뾰족한 점이 아니라 최소 폭(`MOUNTAIN_PEAK_MIN_HALF_WIDTH`)만큼 평평하게 깎여 있고, 폭이 느는 속도도 아래로 갈수록 완만해지는 곡선(`sqrt`)이라 직선 비탈 대신 둥그스름한 능선처럼 보인다. 폭은 보드 폭에서 시계 폭(54칸)을 뺀 실제 빈 공간을 계산해서 정하므로 터미널이 넓을수록 산도 넓어진다(공간이 없으면 안 그려진다). 높이는 4줄 — 시계 디지트 옆에 떠 있는 모양이고 잔디까지는 안 닿는다. 한때는 8줄(시계+빈줄+날짜+빈줄)로 늘려서 잔디 바로 윗줄까지 채웠었는데, 터미널 글꼴 줄간격을 1.0보다 크게(예: Tabby 커스텀 CSS로 1.4) 설정해 둔 환경에서는 한 칸의 세로가 그만큼 더 길어져서 8줄 산이 폭에 비해 탑처럼 길쭉해 보였다 — 글꼴 줄간격은 `process.stdout`로 읽을 수 없어 코드가 자동으로 보정하지 못한다. 그래서 사용자 선택으로 높이를 다시 줄이고, 산이 잔디까지 안 닿는 쪽을 받아들이기로 했다.
- 왼쪽 산 바로 위에 해(`☀️`, 06~17시) 또는 달(`🌕`, 그 외 시간)이 뜬다(이모지로 그린다) — 시(時)만 보고 거칠게 낮/밤을 가른다. 산 위에 정확히 걸리도록, 이 줄도 산 줄과 같은 폭 구성(산 폭 + 간격 + 시계·날짜 칸 폭 + 간격 + 산 폭)을 그대로 맞춰서 보드 가운데가 아니라 산 바로 위로 정렬시킨다.
- 날짜+요일
- 풀밭 사이를 오가는 강아지 한 마리(가끔 냄새 맡거나 멈춰 서고, 드물게 푸들과 마주친다 — 있던 자리에 멈춰 느낌표 두 번(❗❗) → 푸들 쪽으로 빠르게 달려가서 → 맞닿으면 멈춰서 하트 두 번 뿅뿅(💕💕) → 같이 사라진다)
- 밤(해/달 기준으로 밤일 때)에만 부엉이(`🦉`)가 산 능선 바로 옆에 랜덤하게 나타났다 사라진다. 아직 near 봉우리가 시작되지 않은 윗줄(far 봉우리만 있어 능선 옆에 빈 칸이 넉넉한 구간)에서, 그 줄의 실제로 칠해진 폭을 찾아 바로 왼쪽이나 오른쪽에 걸터앉은 것처럼 놓는다. 낮이 되면 보여주던 중이어도 바로 사라진다. Ink의 `position: 'absolute'`로 산 Box 위에 겹쳐 그려서, 산 모양 자체는 건드리지 않는다.

## 폭 — 글꼴 크기를 바꿔도 실시간으로 따라간다

Ink는 루트 `Box`의 너비를 항상 그 보드가 떠 있는 터미널(분할 패널)의 전체 폭으로 강제한다(값을 안 줘도 저절로 그렇게 된다 — `server-status-board` 쪽에서도 실측으로 확인한 동작). 이 보드는 `paddingX: 0` + 테두리(single) 2를 쓰므로, `boardWidth`(풀밭+강아지 줄 폭)를 그 순간의 터미널 폭 - 2로 계산해서 테두리 안쪽을 꽉 채운다(잔디가 2칸짜리 이모지 격자라 2의 배수로 내림한다). 터미널이 아니거나 폭을 못 읽으면 예전 고정값과 같은 82(= `boardWidth` 80)로 되돌아간다.

Node는 터미널 창의 실제 픽셀 크기나 글꼴 크기는 못 보고, 터미널이 보고하는 문자 격자 크기(`process.stdout.columns`/`rows`)만 안다. 그런데 글꼴을 키우거나 줄이면 창 픽셀 크기가 그대로라도 그 격자 크기는 바뀐다 — 그래서 `useTerminalColumns` 훅으로 `'resize'` 이벤트를 구독해, 글꼴 크기를 바꿀 때마다(또는 터미널 패널 자체를 리사이즈할 때마다) `boardWidth`·산 폭·산 모양·잔디 줄을 실시간으로 다시 계산한다. 리사이즈 전후 `terminalColumns`→`boardWidth`→`mountainSideWidth`를 트레이스로 실측해 올바르게 재계산되는 것을 확인했다.

산 모양(`buildMountainRows`)은 랜덤이 아니라 폭만으로 정해지는 결정론적 계산이라, 폭이 바뀔 때 다시 만들어도 깜빡이지 않는다(같은 폭이면 항상 같은 모양). 잔디 줄은 랜덤이라 `boardWidth`가 바뀔 때만(초마다 다시 그리는 시계 틱과는 무관하게, `useMemo`로) 다시 뽑는다 — 매 프레임 다시 뽑으면 배경이 깜빡여 보이던 예전 문제는 그대로 피한다. 강아지(`DogWalk`)는 리사이즈로 `width`(따라서 `maxX`)가 줄어들면, 전에 더 넓었을 때 걷던 `x`가 새 범위를 벗어날 수 있어서 그 값을 새 `maxX` 이하로 당겨 주는 effect를 따로 둔다(트레이스로 `x`가 리사이즈 직후 정확히 새 `maxX`로 클램프되는 것까지 확인했다).

`server-status-board`·`claude-agents-board`는 반대로 내용 기준으로 테두리 폭을 좁히는 쪽이라서, 세 보드를 나란히 맞추려면 각 터미널 패널 폭을 사용자가 직접 맞추면 된다 — 이제 어느 한쪽 범례 문구 길이에 맞춰 역산해 둘 필요는 없다.

### 글꼴을 키우면(터미널이 좁아지면) 깨지던 문제

실시간 리사이즈를 붙인 뒤 글꼴을 키워서(= 터미널 칸 수가 줄어서) 좁아지면 테두리·LED 폰트 격자가 깨지는 문제가 있었다(사용자 실측 보고). 원인은 둘이었다:

1. `boardWidth` 하한이 40이었는데, 시계 줄(산 + 여백 2 + `CLOCK_WIDTH`(54, 폭에 따라 줄지 않는 고정값) + 여백 2)이 실제로 필요한 최소 폭은 산이 0이어도 58이다. `boardWidth`가 58 밑으로 내려가면 시계 줄 내용이 그 폭을 넘어서 Ink가 줄바꿈해 LED 폰트 격자·테두리가 깨졌다(실측 재현: 58 미만에서 발생). `MIN_BOARD_WIDTH`(= `CLOCK_WIDTH` + 여백 2개 = 58)를 하한으로 올려서 고쳤다.
2. 산 폭(`mountainSideWidth`)이 해/달 아이콘(2칸)보다도 좁아지면, `centerText`가 안 잘리고 원문 그대로(2칸)를 돌려줘서 그 칸에 할당된 폭을 넘었다 — 그만큼 줄 전체 폭이 보드 폭을 넘어서 테두리가 깨졌다. `centerText`가 칸보다 긴 글자는 아예 빈 칸으로 바꾸게 고쳤다(해/달은 그 폭 밑에서는 안 보이게 되는 것으로 타협 — 산도 폭 0에서 이미 안 보이게 되므로 같은 맥락이다).

58~70칸 구간을 실제로 렌더해서 60칸(= `MIN_BOARD_WIDTH` 58 + 테두리 2) 이상에서는 완전히 안 깨지는 것, 그보다 좁으면(예: 58칸) 구조적으로 더 줄일 방법이 없어(LED 폰트 자체를 줄이지 않는 한) Ink가 알아서 줄바꿈하는 것까지 확인했다 — 이건 남은 한계이지 버그는 아니다.

## 간격 조정 이력 (사용자 확정 값)

- 좌우 여백은 `paddingX: 0`(산책길 좌우 여백을 최대한 좁힌 값).
- 상하 여백은 `paddingY`/`paddingTop`·`marginTop` 같은 Box padding·margin을 전혀 안 쓰고, 빈 `Box({ height: 1 })`를 필요한 자리에 직접 둬서 줄 수를 맞춘다 — 테두리와 내용 사이, 블록과 블록 사이 모두 margin/padding이 만드는 "숨은" 빈 줄이 안 남게, 전부 실제로 자리를 차지하는 빈 줄로 통일했다(처음엔 `paddingTop: 1`, 그다음엔 `marginTop: 1`을 쓰다가 차례로 빈 Box로 바꿔 달라는 요청을 받아 전부 없앴다).
- 제목(`Y O U   G O T   T H I S`)은 상단 테두리에서 빈 줄 3개만큼 띄운 뒤에 온다. 그 아래 해/달 줄, 산·시계·날짜 줄도 각각 빈 줄 하나씩으로 띄운다.
- 산책길(풀밭+강아지+풀밭) 블록 뒤에는 더 이상 여백을 두지 않는다 — 잔디 줄이 하단 테두리에 바로 닿는다(원래는 `marginTop: 1`을 더 둬서 한 줄 띄웠는데, 그 틈을 없애 달라는 요청으로 뺐다).
- 스크롤/높이 문제는 코드로 더 줄이지 않고, 사용자가 터미널 글자 크기를 줄이는 쪽으로 우회했다.
